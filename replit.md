# 中国語マスター (Chinese Master)

## Overview
中国語マスター is a mobile vocabulary learning application designed to help users master Chinese words. It features intuitive browsing of vocabulary, audio pronunciations, progress tracking, and interactive shuffle tests. The app aims to provide a comprehensive and engaging platform for Chinese language learners, from beginners to advanced students. It operates on a freemium model, offering HSK1 content fully free and gating advanced features for HSK2-6 behind a subscription, making it accessible while providing premium content.

## System Architecture
The application is built with React Native and Expo, utilizing a minimal Express.js backend for static serving. Data persistence is handled locally using AsyncStorage. The UI/UX features a calming teal primary color and warm coral secondary color, with distinct success and alert indicators.

Key architectural decisions include:
- **Dual Memorization Tracking**: Separate tracking for text-based and audio-based memorization allows for varied learning styles.
- **Freemium Model Integration**: Subscription management is handled via RevenueCat, offering HSK1 for free and gating advanced features like detailed examples, full audio playback, and advanced tests for higher HSK levels. The RevenueCat API key auto-switches based on environment: Expo Go uses the test key (`test_...`) so the SDK initializes in Test Store mode without errors, while EAS production builds use the real Apple key. Detection is via `Constants.appOwnership === "expo"` in `client/contexts/SubscriptionContext.tsx`.
- **Dynamic Content Delivery**: Word data is categorized by HSK level (1-6), with varying word counts.
- **Notification System**: Two distinct reminder types (study and sprint) are managed, with user-configurable timings and personalized messages.
- **Sprint Learning Cycle**: A 7-day, 29-cell snake grid map guides users through a structured learning path involving study, review, and test sessions, culminating in special stamp rewards.
- **Panda Stamp Library**: 210 regular panda stamps (panda-stamp-1.png … panda-stamp-210.png) covering emotions (joy, anger, sadness) and fun daily-life scenes, cycled deterministically via `getPandaImage(cellIndex, false, hskLevel?)`. 35 special costume-themed stamps (panda-stamp-special.png … panda-stamp-special-35.png) awarded on test clears, cycled via `getSpecialPandaImage(cellIndex, hskLevel?)`. Both helpers live in `client/data/pandaStamps.ts`. **HSK級ごとに異なるスタンプ**: `NORMAL_OFFSETS`/`SPECIAL_OFFSETS`（HSK1=0/0, HSK2=35/6, HSK3=70/12, HSK4=105/18, HSK5=140/24, HSK6=175/30）でPANDA_STAMP_ORDER(210)/PANDA_SPECIALS(35)を巡回させ、級が違えば原則違う絵柄が出る。`resolveStampValue(cellIndex, isSpecial, hskLevel)` が解決の中心で、AsyncStorage `@chinese_master_earned_stamp_snapshot_v1`（key: `${level}-${cell}-${s|n}` → 通常はstamp number、特別はspecial index）に**獲得時の絵柄をスナップショット**する。一度獲得したスタンプはこのスナップショットを優先するためロジック変更後も絵柄が固定される。`loadStampSnapshot()` は App.tsx 起動時に呼ばれメモリへ展開、`migrateStampSnapshotsIfNeeded()`（移行フラグ `@chinese_master_stamp_snapshot_migrated_v1`）が初回起動時に全6級の `completedDates` を旧マッピング（HSK1相当・cellIndexのみ）でスナップショットへ書き込み、既存ユーザーの既獲得スタンプを完全に保護する。 各スタンプには「○○パンダ」形式の和名が `client/data/pandaStampNames.ts` に登録されており、`PANDA_STAMP_NAMES`（番号1..210のRecord、感情/日常/趣味/食/季節/天気/動物/職業/イベント/性格テーマ）と `PANDA_SPECIAL_NAMES`（衣装テーマに沿った長さ35の配列：王様/車掌/騎士/お姫様/魔法使い等）からなる。`getPandaName(cellIndex, isSpecial)` は `getPandaImage` と同じ `PANDA_STAMP_ORDER` / `PANDA_SPECIALS` インデックスロジックで対応する名前を返し、`SprintStampGalleryScreen` のメイングリッド（スタンプ画像下、`No.X` 表示を置換）と dev preview modal（`S.X` / `No.X` 表示を置換、`numberOfLines={2}`）に表示される。
- **Social Sharing**: Integration with `react-native-view-shot` and `expo-sharing` allows users to share their achievements (panda stamps, progress, quotes) as PNG images. The shared card includes the App Store link (placeholder defined in `client/constants/links.ts` as `APP_STORE_URL` — must be updated with the real Apple App ID before launch). Comment input uses `KeyboardAwareScrollViewCompat` so the share button stays visible above the keyboard.
- **Onboarding and Tutorial**: A guided onboarding process includes an introductory tutorial sprint for new users, ensuring a smooth start.
- **Text-to-Speech (TTS)**: `expo-speech` is used for native Chinese pronunciation of words and example sentences. Region preference (`CN` mainland / `TW` Taiwan / `ALTERNATE`) is persisted in AsyncStorage (`@chinese_master_chinese_region_v1`, default `CN`) via `getChineseRegionPreference` / `setChineseRegionPreference` in `client/lib/storage.ts`. `client/lib/speech.ts` caches it (updated by `setChineseRegionCache`); `speakChinese(text, { wordId? })` and `speakWithLanguage(text, lang, rate, { wordId? })` resolve `zh-CN`/`zh-TW` from the cache, and in `ALTERNATE` mode pick deterministically via djb2 hash parity of `wordId || text` so the same word always uses the same region (and an example sentence inherits its word's region when callers pass `wordId`). The setting lives on `ProfileScreen` as a 3-pill segmented row (testIDs `segment-pronunciation-region-cn|tw|alternate`) just below the silent-mode card; selecting a pill plays a "你好" sample.
- **OTA 詳細表示（プロフィール）**: `client/hooks/useOTAUpdate.ts` の `OtaHistoryEntry` は `branchName` `updateGroup` `channel` `assetsCount` も保持し、`recordCurrentRunningUpdate()` が `Updates.manifest.metadata` から取得して保存。`extractOtaDetail(manifest, fallbackRuntime)` は `Updates.useUpdates()` の `downloadedUpdate` / `availableUpdate` 等の生マニフェストから `OtaDetail` を生成するエクスポート関数（`readManifestMeta` を内部で呼ぶ）。`ProfileScreen` の `OtaDetailRows` コンポーネントが Update ID 全文（`selectable` ＋ Menlo/monospace）、Created at、Branch、Channel、Runtime、Assets 数、Update Group ID（全文 selectable）をまとめて描画し、`updateGroup` がある場合は `https://expo.dev/accounts/_/projects/${projectId}/updates/${updateGroup}` への外部リンクボタン（testID `button-open-eas-dashboard`）を表示。projectId は `Constants.expoConfig.extra.eas.projectId` から取得。
- **OTA 詳細の隠し機能化**: プロフィールのバージョンカードでアプリバージョン部分（`button-toggle-ota-unlock` Pressable, `delayLongPress={5000}`）を**5秒長押し**するとOTA情報ブロック全体（現在/直前/未適用 + 手動チェック）が表示／非表示トグル。`otaUnlocked` state は `false` 初期値でセッション内のみ保持（再起動でリセット）。トグル時に Haptics.notificationAsync で feedback（unlock=Success, lock=Warning）。一般ユーザーには見えず、開発者・サポート用途のデバッグ情報として隔離。
- **OTA 履歴表示（プロフィール）**: `client/hooks/useOTAUpdate.ts` が AsyncStorage `@hskhsk_ota_history_v1` に直近5件の `OtaHistoryEntry`（updateId / createdAt / appliedAt / isEmbedded / runtimeVersion / branchName / updateGroup / channel / assetsCount / message）を保存。`recordCurrentRunningUpdate()` が現在実行中の `Updates.updateId` と最新エントリを比較し、変わっていれば先頭に追加。`useOTAUpdate()` のマウント時と `ProfileScreen` のフォーカス時に呼ばれる。プロフィールのOTAブロックは `Updates.useUpdates()` で `currentlyRunning` `downloadedUpdate` `availableUpdate` `isUpdatePending` `isUpdateAvailable` を購読し、「現在適用中」「直前のバージョン」「未適用のアップデート」の3セクションに分けて表示。未適用が `downloadedUpdate`（次回起動で適用）か `availableUpdate`（未ダウンロード）かを区別し、前者の場合は `Updates.reloadAsync()` を呼ぶ「今すぐ再起動して適用」ボタン（testID `button-apply-pending-ota`）を表示。
- **省電力（フォーカス／AppState 連動アニメ停止）**: `client/lib/appStateBus.ts` で `useIsAppActive()`（`AppState`購読）と `useShouldAnimate()`（`useIsFocused()` × `useIsAppActive()`）を提供。`client/components/AnimatedSprintIcon.tsx` の4つの無限ループ（`HereMarker` `MonsterHop` `ConstantMedAnim` `DecoCycle`）が `useShouldAnimate()` を購読し、スプリントタブが非フォーカス時／アプリがバックグラウンド時に `cancelAnimation` で停止し、復帰時に自動再開する。`DecoCycle` の `setTimeout` チェーンも同様に停止／再開。29マスのスネークマップで常時動作していたReanimatedワークレットがオフ画面で完全停止するのでバッテリー消費が大きく下がる。
- **マイク発音スコアの記録と表示**: `client/lib/micScoreLog.ts` が AsyncStorage 3キーに永続化: `@chinese_master_mic_word_v1`（key: `${wordId}` → `{count, sumScore}`）、`@chinese_master_mic_sprint_cell_v1`（key: `${hskLevel}-${cellIndex}` → `{count, sumScore}`）、`@chinese_master_mic_attempts_v1`（直近500件の `MicAttempt[]`: `{ts, score, source, wordId?, hskLevel?, sprintCellIndex?}`）。`recordMicAttempt(opts)` は word 集計・sprint cell 集計（source が sprint 系の場合）・per-attempt 履歴の3つを同時に更新し、書き込みは `writeChain` (Promise chain) でシリアライズして AsyncStorage の上書きレースを防ぐ。`loadMicScoreLog()` は起動時に `App.tsx` で呼ばれ、ハイドレーション完了時に persisted counter と in-flight に発生したカウンタを**加算してマージ**することで初期化レース時のデータ消失を防ぎ、最後に `notify()` で初期表示を促す。読み出し: `getMicStatsForWordIds(wordIds[])`（複数語合計）、`getSprintCellMicStats(hskLevel, cellIndex)`、`getMicAttempts()`（履歴コピー）。`subscribeMicStats(cb)` で変更通知を購読（StudyScreen / AudioLearningScreen / SprintAudioPlaybackScreen で `micVersion` state を bump）。`InlinePronunciationEvaluator` は新 props `source: "word-detail"|"word-card"|"audio-list"|"sprint-study"|"sprint-audio"` `hskLevel?: HskLevel` `sprintCellIndex?: number` を受け取り、`recordedRef` による per-attempt dedupe で `onResult(isFinal)` と `onEnd(lastTranscript)` の両終端パスから1回だけ記録する（次回 `startRecording` で ref をリセット）。表示は StudyScreen（文字学習レンジカード下）と AudioLearningScreen（音声学習レンジカード下）のバッジ（mic アイコン + 「マイク N回 / 平均 NN」、Colors.light.secondary 系）、SprintStudySessionScreen 完了画面の resultStats 直下（testID `sprint-mic-stats-complete`、固定された `studiedCellIndex` 参照）、SprintAudioPlaybackScreen の再生リスト直上（testID `sprint-audio-mic-stats`）に描画される。
- **Analytics (PostHog)**: `posthog-react-native` is initialized in `client/lib/analytics.ts` using `EXPO_PUBLIC_POSTHOG_API_KEY` and `EXPO_PUBLIC_POSTHOG_HOST` (defaults to `https://us.i.posthog.com`). An anonymous UUID `distinctId` is generated per device and stored in AsyncStorage (`@chinese_master_analytics_distinct_id_v1`); no user PII is collected. Consent state (`unknown` | `granted` | `denied`) is persisted under `@chinese_master_analytics_consent_v1`. **Opt-out model**: on first launch `initAnalytics()` automatically promotes `unknown` → `granted` (persisting it) so analytics is on by default; only an explicit prior `denied` is preserved. The `AnalyticsConsentDialog` component in `client/App.tsx` is intentionally **not displayed** anymore (kept for future region-specific GDPR usage). Users disable analytics anytime via the "利用状況の共有" toggle in `ProfileScreen`, which calls `setAnalyticsConsent("denied")` and opts the SDK out immediately. Events queued before init are flushed on grant or dropped on deny. Screen views are auto-tracked via `NavigationContainer.onReady` + `onStateChange` using the current route name. Custom learning events captured: `word_marked_memorized`, `word_marked_unmemorized`, `sprint_test_answer` (with `hsk_level` + `correct`), `sprint_test_completed` (with `hsk_level`, `accuracy`, `percentage`, `passed`), `quiz_answer`, `speak_button_pressed`, `audio_play` (from both `AudioPlaybackScreen` and `SprintAudioPlaybackScreen`), `onboarding_completed`, `paywall_shown`, `subscription_started`. Session replay is disabled (`enableSessionReplay: false`); IDFA is not collected since no native IDFA module is bundled, so no iOS App Tracking Transparency prompt is required.

### Analytics setup
Register the PostHog credentials as secrets / environment variables before deployment:

- `EXPO_PUBLIC_POSTHOG_API_KEY` — your PostHog project API key (required to enable analytics; without it, the SDK is not initialized and the consent dialog is suppressed).
- `EXPO_PUBLIC_POSTHOG_HOST` — optional; defaults to `https://us.i.posthog.com`. Set to `https://eu.i.posthog.com` for the EU cloud, or your self-hosted host.

Both must be exposed at build time via the `EXPO_PUBLIC_` prefix so they're inlined into the JS bundle. They can also be supplied through `app.json`'s `expo.extra.posthogApiKey` / `expo.extra.posthogHost`.
